## Основание

Эти правила адаптируют принципы [Material Motion](https://m3.material.io/styles/motion/overview) и [Fluent Motion](https://fluent2.microsoft.design/motion) для UMGTransitions. Это не копия design systems и не замена дизайн-ревью: здесь зафиксированы решения, которые можно прямо выразить в Blueprint.

## Назначение движения

Движение должно помогать пользователю понять изменение:

- **enter/exit** — появление или уход контента;
- **state feedback** — подтверждение действия, focus, hover, selection;
- **hierarchy** — порядок элементов и связь контейнера с содержимым;
- **spatial change** — изменение позиции, размера или elevation;
- **progress** — непрерывный процесс, а не декоративная анимация.

Если transition не отвечает ни на одну из этих задач, его лучше не добавлять.

## Длительность и easing

- Движение должно быть быстрым, но различимым: большие элементы и длинная дистанция обычно требуют больше времени.
- `Ease Out` — default для появления; `Ease In` — для ухода; `Ease In Out` — для перемещения между устойчивыми состояниями.
- Linear используйте для постоянного процесса и rotation, не как общий default UI.
- Spring добавляйте для естественной реакции и веса, а не вместо продуманного easing.
- Когда несколько эффектов должны закончиться вместе, используйте [Fit To Time](FitToTime.md), а не подбор Force.

## Хореография и иерархия

- Сначала анимируйте главное, затем поддерживающее.
- Используйте короткий stagger, чтобы направить взгляд по списку или сетке.
- Не stagger-айте огромные группы, если общее ожидание становится заметным.
- Второстепенные элементы можно синхронизировать, чтобы не размывать фокус.
- Для structure-aware хореографии используйте [Composer](Composer.md), а не разрозненные ручные delays.

## Accessibility

- Сохраняйте motion рядом с элементом в focus; движение в другой части экрана отвлекает.
- Избегайте вспышек, резких jump и постоянного бесполезного движения.
- Важное состояние должно быть доступно не только через motion: текст, icon, focus state или звук должны передавать тот же результат.
- Project-level Reduce Motion — приоритет дальнейшего развития Spring. До его появления создавайте спокойный macro-вариант без spring/overshoot для чувствительных экранов.

## Практика UMGTransitions

| Сценарий | Предпочтительный инструмент |
| --- | --- |
| Появление элемента | `From` + ease out opacity/translation |
| Выход элемента | ease in opacity/translation |
| Смена выбранного состояния | короткий easing или умеренный spring scale/color |
| Список/сетка | Composer wave + малый delay offset |
| Связанные transitions | Pipe либо общая макро-функция |
| Точный общий финал | Spring с Fit To Time |
| Счётчик/progress | Float + Event Interval, linear только для реального continuous progress |

Перед выпуском проверьте motion вместе с содержимым, на малом и большом числе элементов, и в варианте без motion.
