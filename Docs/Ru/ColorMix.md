## Назначение

`ColorMix` задаёт путь между цветами для linear/easing-переходов. Промежуточные оттенки зависят от выбранного пространства; численная точность endpoints зависит от расчёта и преобразований.

`ColorMix` применяется к цветовым Transition Value в обычном sampling. Для Float/Vector режим не меняет результат. Активный spring возвращает собственные RGBA-каналы поверх этого sample: HSV/OKLCH не определяют пространство spring-симуляции.

## Почему смешение цветов сложно

У цвета нет единственного «правильного» промежуточного значения. Выбор пространства меняет воспринимаемый результат:

- прямое смешение RGB не обязано давать визуально равномерную светлоту или насыщенность;
- смешение hue требует выбрать направление на цветовом круге: короткий и длинный путь дают разные цвета;
- у нейтральных серых цветов hue не определён, поэтому HSV-переход к/от малого saturation может выглядеть неожиданно;
- perceptual space может при обратном преобразовании дать RGB-значения вне gamut конкретного дисплея или материала;
- alpha — отдельная величина. В текущей модели она интерполируется линейно и не premultiply-ится с RGB.

Это не ошибки самого transition: это разные художественные семантики. Поэтому один глобальный алгоритм не подходит одновременно для opacity, brand-color transition, rainbow indicator и material effect.

## Что делает Unreal Engine

`FLinearColor` хранит линейные RGB-компоненты. Стандартный `FMath::Lerp` для него смешивает каналы напрямую; это хороший default для технических параметров и физически линейного света, но не является perceptual interpolation.

| Средство UE 5.7 | Поведение |
| --- | --- |
| FLinearColor / FMath::Lerp | Поканальная интерполяция linear RGB и alpha |
| LinearRGBToHSV / HSVToLinearRGB | Преобразование представления цвета |
| FLinearColor::LerpUsingHSV | Кратчайшая дуга hue, нормализация hue в 0..360, отдельная alpha |
| Blueprint Lerp Using HSV | Доступ к HSV-интерполяции через KismetMathLibrary |

Проверено по UE 5.7: `Runtime/Core/Private/Math/Color.cpp`, `Runtime/Engine/Classes/Kismet/KismetMathLibrary.h`. В UMGTransitions HSV использует те же conversions и собственный shortest-path код; отдельной нормализации hue после интерполяции в нём нет. OKLCH реализован в плагине. Это описание конкретных API, а не утверждение об отсутствии других color-инструментов в движке.

## Что предлагает UMGTransitions

Плагин делает выбор явным через `ColorMix`, а не меняет стандартное поведение Unreal для всех `FLinearColor`:

- `RGB` использует прямой `FMath::Lerp` четырёх linear channels и остаётся default;
- `HSV` использует engine conversions, интерполирует saturation/value/alpha линейно и идёт по **кратчайшей** дуге hue;
- `OKLCH` преобразует linear RGB в OKLab/OKLCH, интерполирует lightness, chroma, alpha и кратчайшую дугу hue, затем возвращается в linear RGB.

Текущий OKLCH path намеренно не делает скрытый gamut mapping или clamp. Это не меняет authored target color и даёт материалу/свойству исходные linear channels, но требует проверить особенно насыщенные промежуточные цвета в реальном UI.

## Режимы

| Режим | Что интерполируется | Когда выбирать |
| --- | --- | --- |
| `RGB` | Red, Green, Blue и Alpha напрямую | Нейтральный технический default, opacity и близкие по цвету значения. |
| `HSV` | Hue, Saturation, Value и Alpha | Явное движение по оттенку, цветовые индикаторы и эффекты. |
| `OKLCH` | Perceptual lightness, chroma, hue и Alpha | Плавное визуальное смешение заметно разных brand/UI цветов. |


## Производительность и тестирование

### Вычислительная работа

| Вариант | Работа при sample | Числовой benchmark |
| --- | --- | --- |
| RGB | Lerp четырёх каналов | Отдельный замер ColorMix отсутствует |
| HSV | Преобразование обоих endpoints, короткая дуга hue, обратное преобразование | Отсутствует |
| OKLCH | Матрицы, кубические корни, chroma/hue, тригонометрия, обратная матрица | Отсутствует |

Это анализ кода, не A/B скорости. Endpoints HSV/OKLCH сейчас преобразуются при каждом sample. Числа scalar ModeMatrix нельзя использовать как RGB/HSV/OKLCH benchmark.

### Покрытие

| Случай | Состояние |
| --- | --- |
| Shortest hue path | Реализован; выделенный regression не зарегистрирован |
| Серый/почти серый endpoint | Отдельной политики отсутствующего hue нет |
| Alpha | Линейный отдельный канал, без premultiplication |
| Gamut | Нет mapping/clamp, возможны RGB за диапазоном дисплея |
| Spring + ColorMix | Spring считает исходные каналы, отдельного теста сочетания нет |

**Вывод по покрытию:** нельзя обещать измеренное ускорение или безусловно лучшую картинку OKLCH. RGB подходит для прямого смешения каналов; HSV — для обхода оттенков; OKLCH — для управления воспринимаемой светлотой/chroma с проверкой промежуточных цветов. Серые endpoints, прозрачность и gamut требуют визуальной проверки на целевом материале. [Общая методика сравнений](Testing.md#методика-сравнений).
