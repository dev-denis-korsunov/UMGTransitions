## Модель

`FWidgetTransition` — Blueprint-facing описание и runtime instance. Pure nodes возвращают новую структуру, поэтому граф можно безопасно компоновать без скрытой мутации исходного Transition.

`Transition Value` сохраняет до четырёх каналов и semantic type: Float, Vector или Color. Используйте `Make … Transition Value` для входных значений и `As …` для значения из Events.

## Свойства и binding

`Create Widget Transition` задаёт цель и параметры воспроизведения. Виджет обязателен даже при Widget Property = None; при утрате валидности активный переход удаляется. Binding кешируется при добавлении в систему: transition не ищет property path каждый tick.

Поддерживаются compatible float, Vector2D и LinearColor properties, выбранные slot properties, material scalar/vector parameters и быстрые adapters для:

- `RenderOpacity`;
- `RenderTransform.Translation`, `Scale`, `Shear`, `Angle`;
- `RenderTransformPivot`.

Если свойство использует FieldNotify, runtime может отправлять notification по `Event Interval`. Подробности — в [Events](Events.md).

При `Widget Property = None` значение рассчитывается без записи свойства; без явного From стартовые каналы равны нулю. Replace/Skip/Pipe не группируют такие переходы по свойству.

### Параметры Create

| Параметр | Default | Действие |
| --- | --- | --- |
| Widget | Self в Blueprint | Владелец жизненного цикла; обязателен |
| Widget Property | None | Путь свойства или Material.Parameter; None — только value |
| To Value | Выбранное значение | Float / Vector2D / Color |
| Time | 0.2 с | Длительность; у свободного spring завершение по покою |
| Delay | 0 с | Задержка старта |
| Yo Yo | false | Обратная половина прохода |
| Repeat Count | 0 | Дополнительные проходы; −1 бесконечно |
| Repeat Delay | false | Delay перед повтором |
| Add Mode | Replace | Replace / Skip / Pipe |
| ColorMix | RGB | Пространство обычной цветовой интерполяции |
| Event Interval | 0.033 с | Интервал Updated и FieldNotify |

## From

`From(Transition, Use From, From Value, Ignore Delay)` задаёт явную стартовую точку.

- При `Ignore Delay = true` значение записывается сразу, до initial delay.
- При `Ignore Delay = false` запись отложена до tick после delay; точный From на отдельном кадре не гарантируется.
- Если From не задан, runtime читает текущее значение binding при старте.

Это удобно для enter-анимации, когда виджет должен сначала оказаться вне кадра или иметь нулевую opacity.

## Повтор и направление

- `Repeat Count = 0` — один проход.
- Положительное значение — число дополнительных проходов.
- `-1` — бесконечный repeat.
- `Yo Yo` добавляет обратную половину к проходу; Repeat Count затем повторяет пару «туда–обратно».
- `Repeat Delay` повторно применяет Delay перед каждым повторным циклом.

Не используйте бесконечный repeat для фонового декоративного движения без необходимости: он остаётся активной runtime-работой.

## Режимы добавления

Режим работает в пределах пары `(Widget, Widget Property)`:

| Режим | Поведение |
| --- | --- |
| `Replace` | заменяет активный transition и очередь; при отсутствии явного From берёт текущий sample, а новому spring передаёт velocity предыдущего spring. |
| `Skip` | не добавляет transition, если свойство уже активно или имеет Pipe-очередь. |
| `Pipe` | ставит transition в FIFO-очередь и запускает после завершения предыдущего. |

`Pipe` создаёт spring только когда queued transition реально запускается. Новый `Replace` очищает очередь Pipe для того же свойства.

## ColorMix

`ColorMix` выбирает пространство, в котором интерполируются два цвета: `RGB`, `HSV` или `OKLCH`. Это влияет на траекторию промежуточных оттенков, а не на target color.

Подробнее: [Смешение цветов](ColorMix.md).

## Производительность и тестирование

### Конструирование

23.08.2026, UE 5.7 / Mac arm64 Development. 100 000 созданий, мкс/transition; запуск и tick исключены.

| Вариант A/B/C | Мкс/transition | Что измерено |
| --- | ---: | --- |
| A: ручная структура | 0.035 | Заполнение полей в C++ |
| B: Create | 0.034 | Вызов функции библиотеки в C++ |
| C: полная pure-цепочка | 0.121 | Последовательное построение настроенной копии |

**Вывод:** удобство цепочки имеет измеримую цену при массовом создании; она оплачивается при построении, а не каждый tick. Это не benchmark исполнения Blueprint VM. Подробнее: [исходные результаты](History/TestResults.md).

### Pipe: глобальная очередь → keyed FIFO

09.09.2026, UE 5.7 / Mac arm64 Development, 200 выборок на случай. Замер: завершение active → удаление → активация successor. Создание и постановка в очередь исключены. A — исходный зарегистрированный прогон, B — оптимизированный; последовательные замеры.

| Одновременных handoff | A Linear, мкс/tick | B Linear | A Spring | B Spring |
| ---: | ---: | ---: | ---: | ---: |
| 1 | 0.748 | 0.870 | 0.756 | 0.954 |
| 20 | 15.346 | 13.036 | 15.217 | 14.007 |
| 100 | 172.105 | 71.567 | 167.746 | 70.268 |
| 500 | 3324.742 | 380.379 | 3338.487 | 381.599 |

| Этап | Причина изменения |
| --- | --- |
| Глобальная очередь | Повторный поиск active и работа с общим массивом увеличивали цену burst |
| FIFO на пару Widget/Property | Head-index вместо сдвига очереди; снимок active keys вместо повторных поисков |
| Lazy spring | Queued spring создаётся только при активации |

**Вывод:** на 500 свойствах получено около −88.6% стоимости handoff: 3.32–3.34 → 0.38 мс/tick. Для одного handoff ускорения нет. В варианте B стоимость одного handoff — 0.761 мкс linear / 0.763 мкс spring; оптимизация очереди важнее разницы их старта. В архиве также встречается иной исходный запуск; проценты здесь рассчитаны строго по строкам этой таблицы. Подробнее: [методика Pipe](History/PerformanceTests.md#граница-pipe).

### Корректность

| Runtime-тест | Что защищает |
| --- | --- |
| SpecBuilders | Параметры pure-конструктора |
| PropertyBinding.Channels | Чтение/запись стандартных каналов |
| ExplicitFrom | Явный From при нулевом delay |
| AddMode | Replace, Skip, Pipe и сброс очереди |
| PipeOrder | FIFO при изменениях очереди другого свойства |
| YoYo | Обратная половина прохода |

После keyed FIFO записано 15/15 Runtime (09.09.2026). Открытое поведение From после delay описано в [Known Issues](KnownIssues.md#transition-update-path); точное стартовое значение на отдельном кадре не гарантировано этим покрытием.
