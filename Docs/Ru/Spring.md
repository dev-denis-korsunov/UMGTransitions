## Назначение

Spring создаёт инерционное движение для Float, Vector и Color. Все значения runtime представляет четырьмя float-каналами, поэтому один solver обслуживает все поддержанные типы.

Spring выбирайте, когда движение должно передавать вес, реакцию на жест или упругое появление. Для обычного state change сначала проверяйте easing: он проще контролируется и имеет фиксированную длительность.

## Модель

Solver использует аналитическое решение затухающего гармонического осциллятора с фиксированной массой `m = 1`:

```text
x'' + 2 × ζ × ω × x' + ω² × x = 0
```

`x` — смещение от target, `ω` — собственная частота, `ζ` — damping ratio. Для каждого канала есть собственные position и velocity, но общие параметры spring.

Under-damped и critically damped случаи рассчитываются отдельными аналитическими ветками. После состояния покоя значение snap-ается в target.

## Параметры

| Параметр | Смысл |
| --- | --- |
| `Spring Force` | Stiffness coefficient. `160` соответствует default response; большее значение ускоряет движение. |
| `Spring Damping` | Нормализованный UI-control `0..1`, отображаемый во внутренний damping ratio. |
| `Spring Max Speed` | Ограничивает длину velocity; `0` не ограничивает её. |
| `Fit To Time` | Выводит frequency из Time и Damping, чтобы достичь target к заданному дедлайну. |
| `End Tolerance` | Внутренняя относительная константа 0.001; не поле каждого Transition. |

Подробнее о `Fit To Time`: [отдельная страница](FitToTime.md).


## Границы модели

| Ограничение | Практический смысл |
| --- | --- |
| Масса фиксирована: 1 | Force задаёт stiffness |
| Damping 0..1 → ζ 0.15..1 | Overdamped ζ > 1 не представлен |
| Общие параметры четырёх каналов | У каждого канала свои position/velocity |
| Max Speed применяется после шага | При ограничении движение перестаёт быть точным решением исходного уравнения |
| Нет общего value clamp | Диапазон opacity, transform и material определяется потребителем |
| Spring работает с RGBA-каналами | ColorMix не задаёт пространство действующей spring-симуляции |

### Этапы оптимизации

23–24.08.2026, UE 5.7 / Mac arm64 Development, 500 spring без binding. Последовательные этапы разработки; суммарный процент не является контролируемым A/B.

| Этап | Мкс/кадр | Решение |
| --- | ---: | --- |
| Параметры и completion в tick | 11.485 | Исходный путь |
| Кеширование frequency/damping | 8.986 | Вычислять неизменные параметры при старте |
| Squared completion | 8.359 | Исключить Sqrt из проверки покоя |
| Независимый dense spring pass | 7.424 | Считать плотный массив первым проходом |
| Delay внутри spring | 7.368 | Уменьшить обращения к transition |

**Вывод:** приняты изменения организации данных и повторных вычислений. Эти цифры объясняют архитектуру; текущий бюджет системы смотрите в [общем A/B](Testing.md#общий-ab-системы). Подробнее: [история spring](History/OptimizationHistory.md#spring).

### ParallelFor: A/B/C

UE 5.7 / MacBook Pro Apple Silicon / Development Editor. Изолирован только compute spring pass: без UObject, setters и callbacks. A — последовательный проход, B — принудительный ParallelFor, C — parallel при количестве ≥256.

| Spring | A, мкс/кадр | B, мкс/кадр | C, мкс/кадр |
| ---: | ---: | ---: | ---: |
| 64 | 0.518 | 8.336 | 0.540 |
| 128 | 1.069 | 15.688 | 0.986 |
| 256 | 2.129 | 25.802 | 24.543 |
| 500 | 3.828 | 51.405 | 50.417 |
| 1000 | 8.212 | 98.268 | 95.632 |

**Вывод:** на проверенной машине scheduling/barrier дороже вычисления spring. При 500 C медленнее A в 13.2 раза; runtime оставлен последовательным. Это не устанавливает порог для другой архитектуры CPU или существенно больших нагрузок. Подробнее: [ParallelFor](History/OptimizationHistory.md#parallelfor-для-dense-spring-pass).
